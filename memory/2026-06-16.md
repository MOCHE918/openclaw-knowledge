## 后续深度诊断（14:00+）

### 发现：STATE_X每期预测完全一样

修复归一化权重、放大聚类窗口、增加聚类迭代次数后，回测结果**与修复前完全一致**（300期19次=6.33%）。

检查发现无论哪个时期，predictWithStates都输出完全相同的10注：`012 013 014 015 016 017 018 019 023 024`

### 根因定位：NaN Bug

**因果链：**

1. `describeProfile()` 中 `avgOdd: (centers[c].odd * 10).toFixed(1) + '/3'` 把数字存为字符串 `"15.1/3"`
2. `generateFromState()` 中 `Math.abs(odd - profile.avgOdd)` 做数值减法
3. JavaScript: `1 - "15.1/3"` = `1 - NaN` = **NaN**
4. `NaN + 任何数 = NaN`，score全部污染
5. 排序时所有score=NaN → sort稳定，输出顺序 = 循环默认顺序（最小的G6组合012~024）
6. **这是为什么预测永远不变的真正原因**
7. `avgBig` 的地方有 `parseFloat()` 但 `avgOdd` 漏了——不一致性导致的bug

### 关键修复（hidden-state.js）

1. **NaN Bug修复：** G6段和G3段都补上 `parseFloat(profile.avgOdd)`
2. **预测合成重写：** 从 当前态(40%) + 转移目标(35%) + 次近态(25%) 生成，不再用固定权重压制大号态
3. 所有特征权重归一化，k-means++初始化，聚类窗口200期

### 修复后结果

**回测300期：14次命中 = 4.67%（低于随机4.55%）**

### 结论

**STATE_X的"6%"是NaN bug制造的幻象。** 真实STATE_X没有预测能力。

- 前100期的10%命中率只是巧合——小号组合在小号期自然命中的概率
- 后100期的2%命中率反映了小号偏见与中号期的不匹配
- 修复后的4.67% ≈ 随机——**纯统计方法面对独立随机游戏的天花板就是4.55%**
- 用户最初的直觉被验证："如果系统没有干预，你的算法应该无限接近结果才对"
